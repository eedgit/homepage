Ausgewählte Arbeiten

Zwei Projekte, die zeigen, wie ich arbeite: von der ersten Planung bis zum fertigen Ergebnis.

Projekt mit Live-Demo

Filtermodul für Referenzprojekte

Ausgangspunkt war ein typischer Fall aus dem Agenturalltag: Eine Website soll ihre Referenzprojekte so zeigen, dass Besucher schnell finden, was sie interessiert. Dafür habe ich eigenständig ein Filtermodul entwickelt, mit dem Besucher die Projekte nach Art, Branche und Technologie eingrenzen können. Die Ergebnisse erscheinen sofort, ohne dass die Seite neu lädt, und alles funktioniert auch auf dem Handy.

Zuerst habe ich festgelegt, was das Modul können muss, und daraus einen Zeitplan erstellt. Danach habe ich in kleinen Schritten gearbeitet und jeden Zwischenstand getestet. Zum Abschluss habe ich eine Anleitung für die Redaktion und eine für künftige Entwickler geschrieben. Das fertige Modul können Sie in der Live-Demo selbst ausprobieren.

Portfolio-Filter-Modul für WordPress

WordPress 6.8.3 · PHP 8.3 · JavaScript

Ausgangslage war eine statisch gepflegte, nicht responsive Agentur-Website. Dafür habe ich ein WordPress-Plugin entwickelt: Besucher filtern Referenzprojekte nach Typ, Branche und Technologie, und die Ergebnisse aktualisieren sich ohne Seitenreload.

Code auf GitHub

Umsetzung

  • Custom Post Type „Projekte“ mit Taxonomien und ACF-Feldern
  • REST-Controller mit WP_Query, validierten Parametern und schlanken JSON-Antworten
  • Filterlogik im Client mit Fetch API, Debounce und AbortController
  • Pagination, Sortierung, leere Zustände und Object-Cache
  • Barrierearm: Tastaturbedienung und aria-live-Ansage der Trefferzahl

Ergebnis

Alle Tests für Filterung, Pagination, Sortierung, Responsivität und Performance bestanden. Dazu ein Entwickler-Leitfaden und eine Redaktionsanleitung.

  • WordPress
  • PHP
  • JavaScript
  • REST API
  • ACF
  • React
  • PHPUnit
Aus Eigeninitiative

Sichere Anmeldung mit Java

Dieses Projekt habe ich aus eigener Initiative umgesetzt. Fast jede Anwendung braucht eine Anmeldung, und gerade dort zählt Sicherheit. Deshalb habe ich mit Java ein Login-System entwickelt.

Ich habe mit einem lauffähigen Kern begonnen und ihn Schritt für Schritt erweitert. Passwörter werden nicht im Klartext gespeichert, und fehlerhafte Eingaben erkennt das System und gibt eine klare Rückmeldung. Die Anwendung ist in klar getrennte Bausteine aufgeteilt, damit sie sich später leicht um neue Funktionen erweitern lässt. Automatische Tests stellen sicher, dass alles auch nach Änderungen noch funktioniert.

Login-System mit Spring Boot

Java 21 · Spring Boot · MySQL

Ein Login-Backend mit REST-Schnittstelle, sicherer Passwortspeicherung und klarer Schichtentrennung. Gebaut so, dass es sich leicht um weitere Funktionen erweitern lässt.

Code auf GitHub · folgt in Kürze

Umsetzung

  • REST-API mit Spring MVC für Login-Anfragen
  • Geschäftslogik in Service-Klassen, Persistenz mit Spring Data JPA und Hibernate
  • Passwörter mit BCrypt gehasht, Authentifizierung über Spring Security
  • Eingabevalidierung mit Jakarta Validation und passenden HTTP-Statuscodes
  • Tests mit JUnit 5 und Mockito

Ergebnis

Ein funktionsfähiges Login-Backend mit Datenbankanbindung, sauber getrennten Schichten und sicherer Authentifizierung.

  • Java 21
  • Spring Boot
  • Spring Security
  • JPA
  • MySQL
  • Maven
  • JUnit 5
Arbeitsweise

Was mir beim Entwickeln wichtig ist

01 · Verstehen

Erst verstehen, dann programmieren

Bevor ich die erste Zeile schreibe, kläre ich, was die Anwendung wirklich leisten soll. Wenn etwas unklar ist, frage ich nach, denn eine gute Lösung beginnt mit dem richtigen Verständnis der Aufgabe.

02 · Planen

Klein anfangen, oft prüfen

Ich plane meine Arbeit in überschaubaren Schritten: erst ein funktionierender Kern, dann Stück für Stück mehr. So bleibt der Fortschritt sichtbar, und Probleme fallen früh auf.

03 · Testen

Tests gehören dazu

Ich prüfe meine Arbeit mit automatischen Tests. Das gibt mir und dem Team die Sicherheit, dass alles auch nach Änderungen noch funktioniert. Wenn doch etwas hakt, suche ich die Ursache, statt nur das Symptom zu beheben.

04 · Dokumentieren

Verständlich dokumentieren

Ein guter Leitfaden spart dem nächsten Entwickler Stunden. Deshalb halte ich fest, was ich gebaut und geändert habe, für Entwickler genauso wie für die Menschen, die später mit der Anwendung arbeiten.
